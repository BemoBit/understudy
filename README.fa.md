# Understudy

**مدل گران را برای فکر کردن نگه دارید. خواندن و بویلرپلیت را بدهید به یک مدل ارزان.**

Understudy یک پلاگین [Claude Code](https://claude.com/claude-code) است. جلوی این را
می‌گیرد که مدل اصلی شما فایل‌های بزرگ را داخل کانتکست خودش بریزد، و همان کار را به یک
کارگر Haiku می‌سپارد. کارگر فایل‌ها را می‌خواند؛ مدل شما فقط جواب را می‌گیرد.

بدون API key. بدون حساب کاربری. بدون هیچ سرویس خارجی. تفویض از طریق همان `claude`
CLI اجرا می‌شود که روی سیستم دارید، با همان احراز هویتی که همین الان استفاده می‌کنید.

📖 [English documentation](README.md)

---

## مسئله چیست

یک فایل ۱۰۰۰ خطی تقریباً ۱۳٬۰۰۰ توکن است. یک بار بخوانیدش و تا آخر آن نشست در
کانتکست می‌ماند — و در هر نوبت بعدی دوباره فرستاده و دوباره حساب می‌شود. چهار تا از
این فایل‌ها را بخوانید، نیمی از پنجره رفته، پیش از آنکه کار اصلی شروع شود.

و بیشتر این توکن‌ها اصلاً آن چیزی نیست که مدل گران در آن خوب است. «کدام تابع‌ها به
دیتابیس می‌نویسند؟» نیاز به استدلال سطح‌بالا ندارد؛ نیاز به کسی دارد که فایل را بخواند.

## راه‌حل

سه لایه، از سدّ سخت تا پیشنهاد نرم:

| لایه | کارش چیست |
|---|---|
| **هوک‌ها** | `Read` روی فایل بالای ۳۵۰ خط و `cat`/`less` روی همان را رد می‌کنند و مسیر جایگزین را نشان می‌دهند |
| **اسکریپت‌ها** | خودِ تفویض را انجام می‌دهند: ساخت پرامپت، صدا زدن کارگر، تمیز کردن خروجی |
| **اسکیل‌ها** | به ایجنت می‌گویند کِی و چطور اسکریپت‌ها را صدا بزند |

مدل شما هیچ‌وقت از روی متن یک پایپ‌لاین شل سرهم نمی‌کند. یک اسکریپت را با آرگومان‌های
نام‌دار صدا می‌زند و بقیه‌اش کار اسکریپت است.

```bash
bulk-read --question "کدام متدها در دیتابیس می‌نویسند؟" --paths src/UserService.java
```

فایل می‌رود پیش کارگر، جواب برمی‌گردد. کانتکست شما جواب را نگه می‌دارد، نه فایل را.

## پیش‌نیازها

- **Claude Code CLI** — اگر این را می‌خوانید، نصب است
- **[jq](https://jqlang.org)** — `brew install jq` یا `apt install jq`

همین. کل فهرست همین دو تاست. روی macOS و Linux، با `bash` نسخهٔ ۳.۲ به بالا. هیچ چیزی
سراسری نصب نمی‌شود، هیچ پروسه‌ای در پس‌زمینه نمی‌ماند، و هیچ داده‌ای جایی فرستاده نمی‌شود.

## نصب

```bash
claude plugin marketplace add BemoBit/understudy
claude plugin install understudy@understudy
```

یک نشست جدید باز کنید و سلامت نصب را بررسی کنید:

```text
/understudy:doctor
```

این یک بررسی فقط-خواندنی است. اگر بخواهید یک رفت‌وبرگشت واقعی هم تست شود — یعنی
احراز هویت و دسترسی به مدل، به قیمت حدود یک‌دهم سنت — بگویید `/understudy:doctor --probe`.

### نصب از روی کلون محلی

```bash
git clone https://github.com/BemoBit/understudy.git
claude plugin marketplace add ./understudy
claude plugin install understudy@understudy
```

کلون کردن ساده‌ترین راه برای اجرای دستی اسکریپت‌هاست، چون نسخهٔ نصب‌شده زیر یک مسیر
کش با شمارهٔ نسخه قرار می‌گیرد:

```bash
export PATH="$PATH:$HOME/understudy/plugins/understudy/scripts"
understudy-doctor --probe
```

### هزینهٔ کانتکست خودِ پلاگین

```
Always-on:   ~284 توکن به هر نشست اضافه می‌شود
```

فقط توضیح سه اسکیل. هوک‌ها در خود هارنس اجرا می‌شوند و هیچ هزینهٔ توکنی ندارند.

## استفاده

### خودکار

بعد از نصب، هوک‌ها کار را پیش می‌برند. مدل می‌خواهد یک فایل ۹۰۰ خطی را بخواند، هوک
جلویش را می‌گیرد و راه جایگزین را نام می‌برد، و مدل تفویض می‌کند. لازم نیست چیزی بخواهید.

### دستی

هر دو اسکریپت ابزار خط فرمان معمولی‌اند و خودتان هم می‌توانید اجرایشان کنید:

```bash
bulk-read --question "<سؤال>" --paths <file> [<file> ...]

  --question <text>     سؤالی که دربارهٔ فایل‌ها می‌پرسید (اجباری)
  --paths <file...>     فایل‌هایی که فرستاده می‌شوند (اجباری؛ فقط فایل متنی)
  --mode <name>         مود کارگر / سیستم‌پرامپت (پیش‌فرض: bulk-reader)
  --model <name>        تغییر مدل فقط برای همین یک فراخوانی
  --no-line-numbers     فرستادن محتوای خام به‌جای خطوط شماره‌دار
```

```bash
code-write --spec "<چه چیزی ساخته شود>" --reference <file> [--target <path>]

  --spec <text>         چیزی که باید تولید شود (اجباری)
  --reference <file>    فایلی که خروجی باید الگوهایش را رعایت کند
                        (اجباری، قابل تکرار)
  --target <path>       نوشتن در این مسیر به‌جای stdout
  --force               اجازهٔ بازنویسی فایل موجود در --target
  --mode <name>         مود کارگر / سیستم‌پرامپت (پیش‌فرض: code-writer)
  --model <name>        تغییر مدل فقط برای همین یک فراخوانی
```

نمونه‌ها:

```bash
# یک سؤال روی سه فایل
bulk-read --question "یک ریکوئست از روتر تا دیتابیس چه مسیری را طی می‌کند؟" \
          --paths src/router.ts src/controller.ts src/repo.ts

# ساخت تستی که از روی یک تست موجود الگو می‌گیرد
code-write --spec "تست‌های UserService با پوشش مسیرهای خطا" \
           --reference tests/OrderServiceTest.java \
           --target tests/UserServiceTest.java
```

### هر فراخوانی مستقل است

هیچ چیزی بین فراخوانی‌ها به خاطر سپرده نمی‌شود. برای سؤال بعدی، دوباره با همان
`--paths` بپرسید. دوباره فرستادن فایل‌ها آنجا که مهم است رایگان است: فایل‌ها پیش کارگر
می‌روند، نه پیش شما.

## پیکربندی

همهٔ تنظیمات متغیر محیطی‌اند. برای یک پروژه در بلوک `env` فایل
`.claude/settings.json` بگذاریدشان؛ برای همهٔ کارهایتان در `~/.claude/settings.json`.

```json
{
  "env": {
    "UNDERSTUDY_MIN_LINES": "500",
    "UNDERSTUDY_LOG": "/Users/you/.understudy.jsonl"
  }
}
```

| متغیر | پیش‌فرض | کارش |
|---|---|---|
| `UNDERSTUDY_MODEL` | `claude-haiku-4-5-20251001` | مدل کارگر |
| `UNDERSTUDY_BULK_READER_MODEL` | — | مدل فقط برای مود bulk-reader |
| `UNDERSTUDY_CODE_WRITER_MODEL` | — | مدل فقط برای مود code-writer |
| `UNDERSTUDY_MIN_LINES` | `350` | آستانهٔ خطی که بالاتر از آن هوک‌ها خواندن را رد می‌کنند |
| `UNDERSTUDY_DISABLE` | خالی | هر مقداری بگذارید، هوک‌ها خاموش می‌شوند |
| `UNDERSTUDY_TIMEOUT_SECONDS` | `180` | سقف زمانی یک تفویض |
| `UNDERSTUDY_MAX_INPUT_TOKENS` | `150000` | رد کردن درخواست بزرگ‌تر از این |
| `UNDERSTUDY_MODES_DIR` | — | پوشهٔ اضافی برای جستجوی پرامپت مودها |
| `UNDERSTUDY_CLAUDE_BIN` | `claude` | نحوهٔ اجرای CLI |
| `UNDERSTUDY_LOG` | — | نوشتن یک رکورد JSONL به ازای هر تفویض |

مدل هر مود بر `UNDERSTUDY_MODEL` اولویت دارد، و `--model` روی خط فرمان بر هر دو.
چون تولید کد سخت‌تر از خواندن است، این تقسیم منطقی است که کدنویس روی یک مدل میانی
باشد و خواننده روی Haiku بماند:

```json
{ "env": { "UNDERSTUDY_CODE_WRITER_MODEL": "claude-sonnet-5" } }
```

### مودهای دلخواه

*مود* یعنی یک سیستم‌پرامپت روی دیسک. دو مود پیش‌فرض در
`plugins/understudy/modes/` هستند. کافی است فایلی با همان اسم در
`~/.config/understudy/modes/` بگذارید تا جایگزین شود — بدون فورک، بدون نصب دوباره:

```bash
mkdir -p ~/.config/understudy/modes
cp .../modes/bulk-reader.md ~/.config/understudy/modes/
$EDITOR ~/.config/understudy/modes/bulk-reader.md
```

مود جدید هم دقیقاً همین‌طور کار می‌کند. فایل
`~/.config/understudy/modes/sql-reviewer.md` را بنویسید و بعد
`bulk-read --mode sql-reviewer --question ... --paths ...` بزنید.

## واقعاً چقدر صرفه‌جویی می‌شود

جواب صادقانه: **صرفه‌جویی در کانتکست قطعی است، صرفه‌جویی در پول به نشست شما بستگی دارد.**

یک اجرای واقعی روی یک فایل ۹۸۸ خطی:

```
[understudy: bulk-reader · claude-haiku-4-5-20251001 · in 13,014 → out 2,622 tok · $0.049 · 17.5s]
```

آن ۱۳٬۰۱۴ توکن هرگز وارد کانتکست اصلی نشد، پس در هیچ نوبت بعدی دوباره فرستاده نشد —
و صرفه‌جویی مرکب دقیقاً همین‌جاست. در مقابلش: این فراخوانی ۱۷.۵ ثانیه طول کشید و
پنج سنت هزینهٔ خودش را داشت.

پس وقتی می‌ارزد که فایل بزرگ باشد، نشست طولانی باشد، و سؤال از جنس «پیدا کردن» باشد
نه «قضاوت کردن». روی یک فایل ۲۰۰ خطی که می‌خواهید ویرایشش کنید نمی‌ارزد.

این اعداد را دربست قبول نکنید. `UNDERSTUDY_LOG` را روشن کنید و اعداد خودتان را اندازه بگیرید:

```bash
jq -s 'group_by(.mode)[] | {mode: .[0].mode, calls: length,
       input_tokens: map(.input_tokens) | add,
       usd: map(.cost_usd) | add}' ~/.understudy.jsonl
```

## کِی نباید تفویض کرد

اسکیل‌ها این را به ایجنت می‌گویند، ولی خوب است خودتان هم بدانید:

- **ویرایش.** ویرایش به بایت دقیق در کانتکست نیاز دارد. همان ناحیه را با
  `offset`/`limit` بخوانید — خواندن هدفمند هیچ‌وقت بلاک نمی‌شود.
- **دیباگ.** خلاصهٔ کد آن چیزی نیست که باگ را پیدا می‌کند.
- **فایل‌های کوچک.** زیر آستانه، هزینهٔ رفت‌وبرگشت از صرفه‌جویی بیشتر است.
- **تصمیم‌های معماری.** دقیقاً همان چیزی که بابتش پول مدل گران را می‌دهید.

## تفویض دقیقاً چطور کار می‌کند

به ازای هر تفویض یک فراخوانی `claude -p`، عمداً تا حد ممکن لخت:

```bash
claude -p \
  --model claude-haiku-4-5-20251001 \
  --system-prompt "<مود>" \         # کل سیستم‌پرامپت پیش‌فرض را جایگزین می‌کند
  --tools "" \                      # هیچ دسترسی به ابزار
  --safe-mode \                     # بدون CLAUDE.md، پلاگین، هوک و MCP
  --strict-mcp-config \
  --no-session-persistence \
  --output-format json \
  < prompt.txt                      # از stdin، پس هیچ سقف ARG_MAX وجود ندارد
```

هر فلگ دلیل دارد:

- **`--system-prompt`** به‌جای افزودن، سیستم‌پرامپت را *جایگزین* می‌کند، تا کارگر هیچ
  داربستی را حمل نکند که هرگز از آن استفاده نمی‌کند.
- **`--tools ""`** هیچ راهی برای عمل کردن به کارگر نمی‌دهد. متن فایل‌ها از قبل داخل
  پرامپت است، و کارگری که نمی‌تواند عمل کند نمی‌تواند غافلگیرتان کند.
- **`--safe-mode`** همان چیزی است که جلوی فعال شدن هوکِ Read را *داخل* خود تفویض
  می‌گیرد و از بازگشت بی‌نهایت جلوگیری می‌کند؛ ضمناً `CLAUDE.md` شما را از فراخوانی‌ای
  که هیچ استفاده‌ای از آن ندارد بیرون نگه می‌دارد.
- **stdin** دلیل این است که هیچ سقف حجمی برای دور زدن وجود ندارد. تنها محدودیت،
  پنجرهٔ کانتکست خود کارگر است.

### تصمیم‌های طراحی که خوب است بدانید

- **هوک‌ها fail-open هستند.** نبودن `jq`، نبودن `claude`، نبودن اسکریپت‌ها، یا ست بودن
  `UNDERSTUDY_DISABLE` ← خواندن عبور می‌کند. هوکی که وقتی بک‌اندش نیست ایجنت را فلج
  کند، از نبودن هوک بدتر است.
- **هوک‌ها هرگز «allow» صادر نمی‌کنند.** یا رد می‌کنند یا ساکت می‌مانند. یک allow صریح
  خواندن‌هایی را خودکار تأیید می‌کرد که شاید تنظیمات دسترسی شما می‌خواست دربارهٔ آن‌ها
  بپرسد؛ سکوت اجازه می‌دهد جریان عادی دست‌نخورده ادامه پیدا کند.
- **رشتهٔ دستور هرگز eval نمی‌شود.** هوک Bash فقط روی فاصله split می‌کند، با glob خاموش.
  هیچ چیزی از داخل یک دستور نمی‌تواند از داخل هوک اجرا شود.
- **فایل باینری همه‌جا کنار گذاشته می‌شود.** وگرنه به‌صورت آشغال به کارگر می‌رسید و
  جوابی با اعتمادبه‌نفس دربارهٔ هیچ برمی‌گشت.
- **`code-write` بازنویسی نمی‌کند.** اگر واقعاً می‌خواهید، `--force` بدهید.
- **کارگر حق «نه» گفتن دارد.** وقتی نتواند اسپک را برآورده کند، فقط یک خط با
  `ERROR:` برمی‌گرداند و اسکریپت همان را گزارش می‌کند، به‌جای اینکه آن جمله را داخل یک
  فایل سورس بنویسد.
- **حسابداری توکن صادقانه است.** Claude Code پرامپت‌های بزرگ را کش می‌کند و بیشتر
  ورودی را زیر شمارنده‌های کش گزارش می‌دهد، پس خط آمار هر سه را با هم جمع می‌زند.

## تست‌ها

```bash
bash plugins/understudy/evals/run.sh
```

۴۰ کیس: ۱۳ تا برای هوک Read، ۱۵ تا برای هوک Bash، ۱۲ تا برای لایهٔ انتقال. همه روی یک
`claude` قلابی روی `PATH` اجرا می‌شوند، پس نه احراز هویت می‌خواهند، نه تماس شبکه
می‌گیرند، و نه هزینه‌ای دارند. CI آن‌ها را روی Ubuntu و macOS در هر push اجرا می‌کند.

## رفع اشکال

| نشانه | علت و راه‌حل |
|---|---|
| `missing required command(s): jq` | `brew install jq` یا `apt install jq` |
| `The Claude CLI is not authenticated` | `claude auth login` |
| `Model "..." is not available to this account` | `UNDERSTUDY_MODEL` را روی مدلی بگذارید که دسترسی دارید |
| تفویض از سقف زمانی رد شد | `UNDERSTUDY_TIMEOUT_SECONDS` را بالا ببرید، یا فایل کمتری بفرستید |
| `request is ~N tokens, over the budget` | فراخوانی را بشکنید، یا `UNDERSTUDY_MAX_INPUT_TOKENS` را بالا ببرید |
| هوک جلوی فایلی را می‌گیرد که کامل لازمش دارید | تکه‌تکه با `offset`/`limit` بخوانید، یا `UNDERSTUDY_DISABLE=1` بگذارید |
| هوک‌ها اصلاً کار نمی‌کنند | یک نشست جدید باز کنید؛ هوک‌ها موقع شروع نشست بارگذاری می‌شوند |

`/understudy:doctor` همهٔ این موارد را در یک بررسی گزارش می‌کند.

claude plugin uninstall understudy
